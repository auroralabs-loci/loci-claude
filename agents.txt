LOCI: install and setup
=======================

LOCI version: 0.3.60
Canonical source: agents.txt in the loci-claude repository root.

The machine-readable install guide for LOCI: a coding agent can follow it from
top to bottom, and so can a person. It is the twin of README.md's "Install",
"Quick Start" and "Troubleshooting" sections.


WHAT     LOCI IS
------------

LOCI is a Claude Code and GitHub Copilot CLI plugin for C, C++, Rust and Go
projects. It predicts what compiled code will do: execution time, energy,
stack depth and memory. It reads the compiled binary. It never runs the code,
and it never changes the code.

LOCI judges a measurement against a bound (a limit you state, such as "under
200 ns"). Without a bound it reports the number and reasons about it.


BEFORE YOU START
----------------

You need these:

  1. Claude Code (latest) or GitHub Copilot CLI (1.0.90 or newer). On
     Windows, Copilot also needs PowerShell 7 and Git for Windows' bash on
     PATH (the hooks are bash).
  2. Python 3.12 or newer.
  3. uv (https://docs.astral.sh/uv/). uv installs the loci CLI.
  4. A compiled artifact in the project: .elf, .o or .axf.
  5. A cross-compiler for the target, on PATH. Step 4 names the one this
     project needs, and reports compiler_missing when it is absent.
  6. Network access to the LOCI backend, for the timing and energy skills.

These skills need no cross-compiler and no backend: /loci:stack-depth,
/loci:memory-report, /loci:control-flow, /loci:contract.

If you are an agent and uv is missing, stop and give the user the one install
command for their platform. Do not install it yourself: it needs an
interactive password prompt.

  Linux or macOS   curl -LsSf https://astral.sh/uv/install.sh | sh
  macOS (brew)     brew install uv
  Windows          winget install astral-sh.uv


STEP 1: INSTALL THE PLUGIN
--------------------------

Inside a Claude Code session:

  /plugin marketplace add auroralabs-loci/loci-claude
  /plugin install loci@loci

Claude Code from a terminal, for scripts and CI:

  claude plugin marketplace add auroralabs-loci/loci-claude
  claude plugin install loci@loci -y

GitHub Copilot CLI, from a terminal (it reads the same marketplace):

  copilot plugin marketplace add auroralabs-loci/loci-claude
  copilot plugin install loci@loci

The marketplace is public: no credentials. -y confirms the Claude Code install
when there is no terminal; the Copilot commands ask nothing.


STEP 2: INSTALL THE loci CLI
----------------------------

All analysis runs through the loci command. The plugin installs it in the
background at session start, so usually you do nothing here.

Check it:

  command -v loci

If the command is missing, run /loci:setup in the agent session. It installs
the CLI, verifies the environment and repairs what is broken. It is safe to
run twice.

If you cannot run a skill, install the CLI directly, at the version this
plugin release is built against:

  uv tool install -p 3.12 loci-tools==0.2.122


STEP 3: SIGN IN
---------------

Every LOCI analysis needs a signed-in session. The local skills do not reach the
backend, but the CLI still gates them behind a session.

The user must run this in their own terminal, because it opens a browser:

  loci login

Inside a session on either host, the user types this instead:

  ! loci login

If you are an agent, do not run loci login yourself. The browser flow has no
terminal to take over.

Confirm the result:

  loci auth status

It must report signed_in.


STEP 4: RECORD HOW THE PROJECT BUILDS
-------------------------------------

Run this once per checkout, in the project root:

  /loci:init

It writes .loci/build.yaml: the target ISA, the compiler, the build system and
the artifact. Every measurement reads its flags from that file instead of
guessing. LOCI never runs this on its own: until the user does, the analyses
answer not_initialized and stop.

.loci/build.yaml and .loci/build/ are machine-local and gitignored. A fresh
clone has neither, so run /loci:init again there.


STEP 5: VERIFY
--------------

  loci doctor

Doctor prints one JSON envelope: a check per line and a summary. A required
check that fails blocks analysis; a failed optional check is an advisory.

Then run this in the agent session:

  /loci:help

It confirms the plugin is loaded, lists every skill, and shows the recorded
target, compiler and recipe path.


FIRST ANALYSIS
--------------

Ask for one of these in any C, C++, Rust or Go project that has been built:

  "What is the execution cost of main()?"
  "How much ROM and RAM does my build use?"
  "Is my stack safe for TaskMain?"
  "What does the call graph for process_data() look like?"
  "TaskMain must not exceed 4 kB of stack."

The last one states a bound. LOCI drafts it into .loci/contract.yaml and you
apply it. A bound is what lets a later report pass or fail.

Two skills run on their own, on both hosts: loci-preflight in /plan mode and
loci-post-edit after an edit to C, C++, Rust, Go or Python source.


WHEN SOMETHING FAILS
--------------------

Match the error code in the report, then run the skill:

  not_initialized     /loci:init - the USER runs it, see rule 4
  recipe_stale        /loci:init
  recipe_tampered     /loci:init
  recipe_invalid      /loci:init
  compiler_missing    /loci:init
  arch_mismatch       /loci:init
  outside_target      /loci:init
  compdb_absent       regenerate the compile database - NOT /loci:init
  auth_required       loci login, in the user's own terminal
  loci: not found     /loci:setup

A project with no compile database is initialized off its linked binary:
stack-depth, memory-report and control-flow work, the timing skills refuse
with compdb_absent, and error.message names the generators that make one.

If a skill did not trigger at all, check these:

  1. loci-preflight runs only in /plan mode.
  2. loci-post-edit runs only after an edit to C, C++, Rust, Go or Python source.
  3. Both need a compiled artifact. Build the project first.
  4. LOCI is inactive in a directory where no build file declares a build.

If nothing works, run /loci:bug-report. It writes a full diagnostic report.


RULES FOR AGENTS
----------------

  1. Do not install a prerequisite for the user. Give the command instead.
  2. Do not run loci login. Ask the user to run it.
  3. Do not run loci cockpit. It takes over the terminal and never exits.
  4. Do not run /loci:init unless the user asked. It writes files into their
     project, so which projects LOCI runs on is their choice: name it and stop.
     Repairing a recipe that already exists is different.
  5. Report the plugin version as the LOCI version. The CLI version is internal.
